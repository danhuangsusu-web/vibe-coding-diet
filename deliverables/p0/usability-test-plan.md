# 食刻 AI P0 可用性测试方案

## 目标与参与者

验证用户能否在不解释架构的前提下完成餐食输入、确认、理解结果和记录管理。建议招募 5 名 22–32 岁、每周至少吃两次中式外卖或食堂餐、没有参与本项目开发的人。测试不询问身高、体重、BMI、疾病或真实减重目标；统一使用虚构演示资料。

## 方式

- 每人 15–20 分钟，使用微信开发者工具模拟器或已配置正式 AppID 的真机环境。
- 主持人只读任务，不解释按钮位置；参与者边操作边说出理解。
- 记录完成/失败、耗时、求助点、误解和原话。不记录真实餐食照片；图片任务使用仓库合成素材。

## 任务

1. **文字记录**：输入“番茄炒蛋配一小碗米饭”，确认识别结果并找到热量区间。
2. **不确定做法**：输入“茄子豆角”，说明系统为什么要求选择做法，并完成至少一项修改。
3. **图片输入**：使用指定合成菜单截图，找到隐私提示，确认哪些菜被识别。
4. **理解结果**：用自己的话解释红/黄/绿灯、热量区间和“当前餐参考额度”的含义。
5. **记录管理**：保存一餐，在首页找到汇总，在历史中打开详情，再删除该测试记录。
6. **设置影响**：修改每日建议范围，说明该设置影响的是之后的什么结果。

## 成功标准

- 至少 4/5 人无需主持人指路即可完成文字主流程和记录删除。
- 至少 4/5 人正确理解“区间不是精确值”，且不会把灯位理解成医学诊断。
- 至少 4/5 人能发现不确定做法需要自己确认。
- 所有人都能在图片页看到第三方分析与不长期保存提示。
- 任何导致无法继续主流程的问题记为 P0 阻断缺陷；措辞或发现性问题进入 P1 候选，不在步骤 24 临时扩功能。

## 单人记录模板

```md
参与者编号：U01（不记录姓名）
设备/模拟器：
任务 1：完成/失败；耗时；求助次数；观察
任务 2：完成/失败；用户如何理解“待选择做法”
任务 3：完成/失败；是否看到隐私提示
任务 4：对区间、灯位、参考额度的原话
任务 5：完成/失败；保存、查找、删除的卡点
任务 6：完成/失败；对设置影响的理解
最困惑的一处：
最有价值的一处：
是否出现阻断缺陷：
```

## 测后问题

1. 哪一步最不确定？
2. 你认为热量数字有多精确？为什么？
3. 看到黄灯或红灯时，你觉得系统是在评价食物还是评价你？
4. 你是否愿意在真实场景使用图片输入？隐私说明是否足够？
5. 只允许改一处，你会改什么？
