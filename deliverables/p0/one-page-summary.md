# 食刻 AI：让中式外卖的饮食判断更可信

**定位**：面向 22–32 岁城市职场人的微信小程序 P0，也是一个 AI 产品经理作品集项目。用户用一张餐食图片、菜单截图或一句中文描述记录一餐，确认识别结果后获得热量区间、动态红黄绿灯和 1–2 条可执行建议。

## 为什么做

传统记餐工具要求搜索食物、称重和输入克数，但中式外卖的份量、用油和做法本来就不标准。食刻 AI 不承诺从单张图片得到精确热量，而是降低输入成本，并用区间和不确定性帮助用户做当下选择。

## 核心方案

```text
图片 / 文字 -> AI 结构化识别 -> 用户确认 -> 确定性规则评估 -> 保存与回看
```

- **AI 负责理解**：菜品、受控食材标签、做法、份量档位、置信度和不确定性。
- **规则负责判断**：热量区间、当天剩余额度、红黄绿评级、原因和固定建议 ID。
- **用户保留控制权**：确认前不评级、不保存；未知食材或做法先要求补充，用户明确跳过后才使用宽范围保守估算。
- **隐私边界**：图片仅用于当次识别，不落库；不采集身高、体重、BMI、疾病等敏感健康数据。

## P0 交付

- 五页微信小程序：今日首页、餐食输入、识别确认、评估结果、历史与设置。
- 文字和单张图片两条真实 AI 路径，20 秒停止等待、稳定错误码和可恢复状态。
- PostgreSQL + Prisma 记录闭环，`clientRequestId` 唯一索引保证保存幂等。
- 38 个稳定 ID 的 AI 评测集：26 个文字、12 个确定性合成图片；原始失败结果全部保留。
- 292 个自动化测试，以及独立的真实 HTTP/数据库闭环验证。

## 可量化结果

| 指标 | 基线 | 一次有限迭代后 |
| --- | ---: | ---: |
| 结构化合法率 | 52.6% | 84.2% |
| 主要菜品准确率 | 36.1% | 78.7% |
| 关键做法准确率 | 34.4% | 63.9% |
| 建议相关率 | 80.0% | 96.2% |
| 延迟 P50 | 13.251 秒 | 2.236 秒 |
| 延迟 P90 | 20.012 秒 | 5.128 秒 |

迭代关闭了模型长思考、限制 1,200 输出 token，并强化多菜拆分和缺失做法的保守输出；有限词表只增加用户批准的 `TOMATO` 与 `FISH`。两轮 76 次合成评测的可计算标价成本合计约 0.091 元，14 次调用没有 usage，可能仍产生费用。

## 已知局限与下一步

三项模型指标仍未达目标，且图片评测素材不是实拍照片。P0 不通过删除失败样本、放宽 Schema 或继续扩词来“达标”。完成 P0 后，P1 才会单独设计真实拍摄评测、完整食材分类、可追溯营养数据、可选数量/自然单位/重量区间，以及“真机调试（需正式 AppID）”、HTTPS 和域名配置。
